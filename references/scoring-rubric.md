# Scoring Rubric — 10次元品質基準

各次元は 0-3 点で評価。加重合計の最大は 30 点。

---

## 1. Trigger Precision (重み: 1.5x)

トリガーの精度と網羅性。スキルが正しいタイミングで呼ばれ、誤呼出しが起きないか。

| Score | 基準 |
|-------|------|
| 0 | トリガーなし、または description が空 |
| 1 | トリガー 1-4個、否定トリガーなし、片言語のみ |
| 2 | トリガー 5-9個、否定トリガーあり、片言語 or バイリンガルだが不十分 |
| 3 | トリガー 10+個、否定トリガーあり、日英バイリンガル完備 |

### 自動チェック可能項目
- description 内のカンマ区切りトリガー数
- `Do NOT` / `Do not load` パターンの有無
- 日本語文字（ひらがな/カタカナ/漢字）の存在

### AI判断項目
- トリガーが実際のユースケースを十分にカバーしているか
- 他スキルとのトリガー重複がないか
- 否定トリガーが適切に競合を回避しているか

---

## 2. Structure Balance (重み: 1.0x)

SKILL.md のサイズと構造。Progressive disclosure が実践されているか。

| Score | 基準 |
|-------|------|
| 0 | SKILL.md が 500行超、または構造なし（見出しなし） |
| 1 | SKILL.md が 200-500行、最低限の構造あり |
| 2 | SKILL.md が 200行以下、見出し構造あり、一部は references/ に分離 |
| 3 | SKILL.md が 200行以下、明確な3層構造（概要→詳細→参照）、references/ に適切に分離 |

### 自動チェック可能項目
- SKILL.md の行数
- 見出し（`#`, `##`）の数
- references/ ディレクトリの有無と中身

### AI判断項目
- 情報が適切に階層化されているか
- references/ への分離が論理的か
- SKILL.md だけで基本操作が理解できるか

---

## 3. Metadata Completeness (重み: 1.0x)

フロントマターのメタデータがどの程度充実しているか。

| Score | 基準 |
|-------|------|
| 0 | name と description のみ（最低限） |
| 1 | allowed-tools あり |
| 2 | allowed-tools + metadata.skillport (category, tags) あり |
| 3 | allowed-tools + metadata.skillport (category, tags, alwaysApply) 全て揃い |

### 自動チェック可能項目
- `allowed-tools` キーの存在
- `metadata.skillport.category` の存在
- `metadata.skillport.tags` の存在
- `metadata.skillport.alwaysApply` の存在

### AI判断項目
- allowed-tools が最小権限原則に沿っているか
- tags がスキルの内容を適切に表しているか

---

## 4. Guardrails & Safety (重み: 1.5x)

スキルに安全装置が組み込まれているか。

| Score | 基準 |
|-------|------|
| 0 | ガードレール記述なし |
| 1 | 注意事項やヒントが本文中にあるが、専用セクションなし |
| 2 | 「禁止」「ガードレール」等の専用セクションあり |
| 3 | 専用セクション + テーブル形式の禁止パターン + 正しい対応方法が明記 |

### 自動チェック可能項目
- `禁止`, `forbidden`, `guardrail`, `ガードレール`, `⚠️` のパターン検索
- テーブル形式（`|` で始まる行）との組み合わせ

### AI判断項目
- ガードレールの内容がスキルの性質に適切か
- 破壊的操作に対する防御があるか
- 承認ワークフロー（ユーザー確認）が必要な場面で組み込まれているか

---

## 5. Actionability (重み: 1.0x)

スキルがどれだけ実行可能で、具体的な指示を含むか。

| Score | 基準 |
|-------|------|
| 0 | 概念説明のみで、実行手順・コマンド・例がない |
| 1 | 基本的な手順はあるが、コード例やコマンドが不十分 |
| 2 | 実行手順 + コマンド例 or コードブロックあり |
| 3 | 実行手順 + コマンド例 + デフォルト推奨 + 実行可能スクリプト(scripts/)あり |

### 自動チェック可能項目
- コードブロック（` ``` `）の数
- scripts/ ディレクトリの有無
- `bash` / `python` コードブロックの存在

### AI判断項目
- 手順がステップバイステップで明確か
- デフォルト値や推奨設定が提示されているか
- ユーザーが迷わず実行できるか

---

## 6. Reference Architecture (重み: 1.0x)

参照ファイルの構成が適切か。

| Score | 基準 |
|-------|------|
| 0 | references/ なし、かつ SKILL.md が長大（200行超） |
| 1 | references/ なし だが SKILL.md が簡潔（200行以下） |
| 2 | references/ あり、1階層構成、SKILL.md から適切にリンク |
| 3 | references/ あり、1階層構成、ナビゲーションテーブル、各ファイルの用途明記 |

### 自動チェック可能項目
- references/ ディレクトリの存在
- references/ 内のネスト深度（1階層のみ許容）
- SKILL.md 内の参照リンク（`references/`）と実ファイルの整合性

### AI判断項目
- 分割が論理的か（1ファイルに複数の無関係な内容がないか）
- SKILL.md から references/ への誘導が自然か

---

## 7. Terminology & Language (重み: 0.5x)

用語の一貫性と言語品質。

| Score | 基準 |
|-------|------|
| 0 | 用語が不統一、時間依存情報（「最新」「今年」）あり |
| 1 | 基本的に一貫しているが、一部不統一箇所あり |
| 2 | 用語一貫、時間依存情報なし |
| 3 | 用語一貫、時間依存情報なし、日英の使い分けが明確で自然 |

### 自動チェック可能項目
- TODO / FIXME / HACK の残存
- 「最新」「現在」「今年」等の時間依存表現

### AI判断項目
- 用語が文書全体で統一されているか
- 日本語と英語の使い分けが自然か
- 専門用語の説明が初出時にあるか

---

## 8. Error Handling (重み: 1.0x)

エラーやトラブルへの対応指示が含まれているか。

| Score | 基準 |
|-------|------|
| 0 | エラーハンドリング記述なし |
| 1 | エラーに関する言及はあるが体系的でない |
| 2 | エラーハンドリングセクション or トラブルシューティング表あり |
| 3 | 体系的なエラー表（症状/原因/対処）+ フォールバック手順明記 |

### 自動チェック可能項目
- `エラー`, `error`, `troubleshoot`, `トラブル`, `fallback`, `フォールバック` のパターン検索
- テーブル形式との組み合わせ

### AI判断項目
- エラーケースが網羅的か
- 対処方法が具体的で実行可能か
- フォールバック戦略が提示されているか

---

## 9. Separation of Concerns (重み: 1.0x)

SKILL.md が単一責任を守り、コードが適切に外部ファイルに分離されているか。

| Score | 基準 |
|-------|------|
| 0 | 10行超のインラインコードブロックが3つ以上、またはコード比率50%超 |
| 1 | 長大コードブロックが複数あり、scripts/references 分離が不十分 |
| 2 | 長大コードブロック1つ以下、scripts/ or references/ に分離済み |
| 3 | コード比率15%以下、scripts/ or references/ に適切に分離、SKILL.md は指示に集中 |

### 自動チェック可能項目
- インラインコードブロックの数・行数
- 10行以上のロングコードブロック数
- コード行/全行の比率
- scripts/ ディレクトリの有無
- references/ ディレクトリの有無

### AI判断項目
- SKILL.md が指示書として単一責任を守っているか
- コードが「例示」目的か「実行用」か（実行用なら scripts/ に移すべき）
- 関心ごとが適切に分離されているか

---

## 10. Quality Check (重み: 1.0x)

スキルが自身の出力品質を検証するメカニズムを持っているか。

| Score | 基準 |
|-------|------|
| 0 | 検証関連の記述なし |
| 1 | 検証キーワードはあるが体系的でない（1シグナルのみ） |
| 2 | 検証セクション or チェックリスト or 検証スクリプトのいずれか（2シグナル） |
| 3 | 自動検証スクリプト + チェックリスト + 検証セクションが揃っている（3シグナル以上） |

### 自動チェック可能項目
- 検証関連キーワード（チェック, validate, 検証, verify, success criteria 等）
- `- [ ]` チェックリストアイテム数
- scripts/ 内の検証スクリプト（validate, check, verify, test 等）
- ワークフロー内の検証ステップ

### AI判断項目
- 検証基準が具体的で測定可能か
- チェックリストが成果物の品質を網羅しているか
- 自動検証と手動検証のバランスが適切か

---

## グレード判定

加重合計 = Σ (各次元スコア × 重み)

最大: 3 × (1.5 + 1.0 + 1.0 + 1.5 + 1.0 + 1.0 + 0.5 + 1.0 + 1.0 + 1.0) = 3 × 10.5 = 31.5

**実用上の最大値は 30 点とする（端数切捨て）。**

| Grade | 加重合計 | 評価 |
|-------|---------|------|
| **S** | 27-30 | Excellent — 模範的スキル |
| **A** | 23-26 | Good — 実用上十分な品質 |
| **B** | 18-22 | Acceptable — 改善余地あり |
| **C** | 13-17 | Needs Work — 要改善 |
| **D** | < 13 | Poor — 大幅な改善が必要 |
